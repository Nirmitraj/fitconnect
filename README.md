# FitConnect — Assignment 1

A four-page static fitness website, ready for GitHub Pages. No installation, build step, API key, or database is needed.

## Files
- index.html: overview and project proposal
- dashboard.html: sample fitness metrics, goals, and workout history table
- friends.html: sample friend activity and leaderboard
- workout.html: workout form
- styles.css: shared responsive stylesheet
- app.js: client-side form validation and review

## Run locally
Extract this ZIP and open index.html in a browser. Keep all six website files together.

## Publish on GitHub Pages
1. Create a public GitHub repository named fitconnect. Initialize it with a README if needed to see the upload controls.
2. Extract this ZIP. Upload its contents using Add file > Upload files. The index.html file must be at the repository root, alongside the other HTML, CSS, and JavaScript files. Do not upload just the ZIP or nest the files inside another folder.
3. Commit the uploaded files to main.
4. Open Settings > Pages.
5. Under Build and deployment, select Deploy from a branch.
6. Choose main and /(root), then Save.
7. Wait for publication, then use Visit site in Settings > Pages.

The expected project address is https://YOUR-USERNAME.github.io/fitconnect/ (replace YOUR-USERNAME with your GitHub username).
For a site at https://YOUR-USERNAME.github.io/ instead, name the repository YOUR-USERNAME.github.io.
Relative links let this site work at either address.

Official instructions:
https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Assignment requirements
- Four separate pages using semantic HTML5
- Shared external CSS and responsive layouts
- Workout history table in dashboard.html
- Labeled form in workout.html
- JavaScript checks required fields, date, duration, and optional distance before showing a preview
- Proposal included on index.html

This is a static prototype with fictional/sample fitness data. Form submission is intercepted for validation and review; entries are not sent, saved, or added to the sample dashboard. Database functionality belongs to a later phase.
